# in-da-club

Единое frontend-приложение для встроенного блока Mindbox на `coral.ru`. Блок определяет состояние клиента и показывает один из сценариев CoralBonus:

- клиенту без карты — преимущества программы и оформление карты;
- держателю карты — персонализированные преимущества с учётом числа поездок и уровня Silver, Gold или Platinum.

В обычном режиме приложение получает состояние клиента из `localStorage` и API. Правила преобразования числа поездок в сегмент находятся в `unified/src/segmentation/routing.json`.

## Требования и установка

Требуется Node.js 22.22.2 или новее. Версия для nvm зафиксирована в `.nvmrc`.

```bash
nvm use
npm ci
```

Все команды запускаются из корня репозитория.

## Архитектура

Проект использует модульную структуру без формального разделения на слои FSD:

```text
unified/
  public/
    assets/
      no-card/             ресурсы сценария без карты
      cardholder/          ресурсы держателя карты
      shared/              общие ресурсы сценариев
      intro/               ресурсы вступительного блока
  src/
    app/                   запуск, dev-preview, маршрутизация и состояния экрана
    segmentation/          JSON-правила, конфигурация и типы сегментов
    benefits/              отображение преимуществ обоих сценариев
    card-activation/       оформление и активация карты
      api/                 HTTP- и Mindbox-интеграции
      model/               профиль, согласия и справочные данные
      ui/                  DOM-представления шагов активации
    customer/              профиль, клиентский контекст и бронирования
    shared/                общий browser runtime и базовые SCSS-инструменты
    styles/                точка подключения стилей приложения
tests/                     контрактные тесты конфигурации репозитория
scripts/                   служебные скрипты, включая Typograf
*.config.base.ts           общая конфигурация Vite и Vitest
graphify-out/              граф файлов и зависимостей
```

`app` собирает приложение из самостоятельных предметных модулей. При обычном запуске `client-router.ts` выбирает сценарий, `segmentation` определяет сегмент, а `benefits` отображает его содержимое. Сценарий без карты может открыть процесс из `card-activation`.

Модульные тесты находятся рядом с проверяемым кодом. Корневой каталог `tests/` содержит только проверки общих контрактов репозитория и сборочных команд.

Карта зависимостей находится в [`graphify-out/GRAPH_REPORT.md`](graphify-out/GRAPH_REPORT.md).

## Команды

| Команда | Что выполняет |
| --- | --- |
| `npm run dev` | Запускает Typograf и единый dev-сервер. |
| `npm run build` | Запускает Typograf, проверяет TypeScript и собирает единый HTML-блок. |
| `npm run typograf` | Нормализует пользовательские строки в `unified/src`. |
| `npm run typecheck` | Проверяет TypeScript без генерации файлов. |
| `npm test` | Запускает контрактные и модульные тесты. |

Typograf является обязательным первым шагом `dev` и `build` и может изменить строки в исходных файлах. Для проверки без изменения файлов используйте `npm run typecheck` и `npm test`.

## Dev-preview

В dev-режиме приложение монтируется в `#monkey-app`. Query-параметры позволяют принудительно показать нужный сценарий без запросов к клиентским API.

Сценарий без карты:

| Параметр | Сегмент |
| --- | --- |
| `?cb_client=0` | `new-client` |
| `?cb_client=1` | `regular-1` |
| `?cb_client=2` | `regular-2` |
| `?cb_client=3` | `regular-3` |

Сценарий держателя карты:

| Параметр | Сегмент |
| --- | --- |
| `?ride=0` | `inactive` |
| `?ride=1` | `one-trip` |
| `?ride=2` | `two-trips` |
| `?ride=3` | `three-plus` |

Если переданы оба параметра, приоритет имеет `ride`. Отсутствующие или некорректные параметры не включают preview: приложение использует обычную маршрутизацию. В production параметры игнорируются, а код dev-preview удаляется из сборки.

## Production

`npm run build` создаёт `unified/dist/in-da-club.html` — готовую `<script>`-обёртку для блока Mindbox. На целевой странице приложение ожидает контейнер:

```html
<div data-in-da-club-root></div>
```

Локальные ресурсы находятся в `unified/public/assets`. В production сохраняются существующие публичные CDN-пути сценариев `bez-kart` и `s-kartami`, чтобы не менять внешний контракт размещения ресурсов.

## Проверка изменений

- После изменения TypeScript выполните `npm run typecheck` и `npm test`.
- После изменения сегментов, ресурсов или build-конфигурации выполните `npm run build`.
- DOM-классы, `data-block-id` и SCSS образуют единый контракт и должны изменяться совместно.
- После изменения структуры или зависимостей обновите граф командой `graphify update .`.
